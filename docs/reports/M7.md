# M7 report (2026-11-28): second-wave signals

> NOT APPROVED FOR LIVE DATA. Mock telcos only. Self-conducted; no independent review.

## What was added
Four CAMARA signals, recommended after the landscape check of GSMA Open Gateway / CAMARA, through the existing pipeline:

| Signal | Scope | CAMARA definition pinned (official repo, tag, commit) | Platform answer |
|---|---|---|---|
| `NUMBER_RECYCLING` | `number-recycling:check` | NumberRecycling r3.3 (`ce69c2f`) `/check` | TRUE = number reassigned since the date |
| `KYC_TENURE` | `kyc-tenure:check` | Tenure r3.4 (`e00e699`) `/check-tenure` | TRUE = continuous tenure of at least N days |
| `DEVICE_LOCATION` | `device-location:check` | DeviceLocation r4.3 (`c8cb61f`) `location-verification /verify` | TRUE inside, FALSE outside, PARTIAL = UNAVAILABLE |
| `DEVICE_ROAMING` | `device-roaming:check` | DeviceStatus r2.2 (`555e31f`) `device-roaming-status /retrieve` | TRUE = roaming; country discarded |

Coverage in the sandbox: telco A (CAMARA) all four; telco C (aggregator) recycling and tenure; telco B none (NOT_SUPPORTED). Migration `006` adds the registry rows but **no coverage**.

## What was deliberately not built
* **Number Verification**: needs a device-to-operator redirect flow, not a server-to-server check; design note and decision D-008 (`docs/design/number-verification.md`).
* **KYC Fill-in**: returns personal data, not a signal. **Device connectivity status**, **location retrieval** and **geofencing**: weak fraud value and/or they reveal where or when a person is reachable (`docs/privacy/second-wave-signals.md`).

## Security and privacy controls (all tested in `tests/security/m7-second-wave.test.ts`, 28 tests)
* Same chain as every signal: mTLS, bound token, signed request, scope, entitlement, quotas, consent that **names the signal**, uniform refusals, kill switches that fail closed.
* Strict schemas and meaning checks: real calendar dates, no future dates, look-back and tenure caps, coordinate ranges, **radius 2,000 to 200,000 m**, no extra properties.
* Adapter responses are schema-strict; wrong types, extra fields, errors and malformed JSON are UNAVAILABLE and unbilled; PARTIAL is UNAVAILABLE.
* Location: a separate per-subject hourly cap (default 4), coordinates never stored or logged (asserted over logs, audit sink, audit table, usage and request log), roaming country never reaches the participant.
* Mock telco A validates the request shape against the pinned definitions (a wrongly built request is a 400, so it can never look like a success).

## Threat model, risks, gates
New abuse cases AB-11 (location triangulation), AB-12 (history or travel profiling), AB-13 (partial or hostile answer read as "no"), all traced. New residual risks R-029..R-032 and gate G3a (legal and privacy opinion for these signals).

## Not done
No real telco has been tested; no load test of the new signals; the legal basis for location, roaming, tenure and recycling is not assessed; the cross-participant location cap and anomaly alert (R-029) are open.
