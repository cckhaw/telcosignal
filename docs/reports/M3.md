## Acceptance
**Enumeration** (m3-abuse): a sequential 9-number range scan with no consent produces uniform 403 answers (no existence oracle), exactly one flag per kind per window (SEQUENTIAL_RANGE, CONSENT_PROBING), an audit record and a SIEM-style security event per flag; bulk lookups with valid consents raise HIGH_DISTINCT_SUBJECTS; normal use of another participant is not flagged. No phone number appears in logs, flags, audit rows, Redis keys or Redis set members (keyed hashes only). Auto-suspend suspends only the offender through a narrow SECURITY DEFINER function; the application role cannot write kill switches directly.
**Fault injection** (m3-resilience): HTTP 500s, timeouts, malformed/oversized/wrong-typed answers open the breaker; while open, no telco call is made and the answer is UNAVAILABLE (never a fabricated FALSE), not billed; other telcos are unaffected; half-open allows one probe, success closes and failure re-opens; a flood of numbers the telco does not know (404 / rc=14) cannot trip the breaker (no DoS via enumeration); NOT_SUPPORTED is still answered while open; bulkhead caps in-flight calls per telco and always releases slots; deterministic-clock unit tests for the state machine.
**Statements reconcile** (m3-metering): generated from a single REPEATABLE READ snapshot by a dedicated billing role. Hard-coded expectation from known traffic: bank A 1210 (12 billable queries), bank B 420 (6), telco costs A 330 / B 164 / C 84, margin 1052. Each statement stores a digest over the ordered ids of the exact usage rows it covers; recomputed independently in the test. Telco settlement lines equal the sum of participant `byTelco` counts per (telco, signal). Failures, NOT_SUPPORTED and consent rejections are never billable (DB CHECK + tests); usage and statements are append-only for every role; generation is idempotent; missing prices are reported, never guessed.
