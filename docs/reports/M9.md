# M9 report (2026-11-28): residual-risk items that could be fixed in code

> NOT APPROVED FOR LIVE DATA. Self-conducted; no independent review.

The residual-risk register (`docs/release/residual-risks.md`) has 33 items. Most cannot be closed by a code change: they need a decision, a vendor, an owner, production data or an outside party. This milestone fixed the ones that can be closed in the repository, with tests.

| Item | What changed | Proof |
|---|---|---|
| R-009 fixed-window limits | Quota counters are sliding windows (current window plus the previous one weighted by overlap) | `m9-risk-fixes`: a burst split across a window edge is held to about one window's worth; allowance returns as the window slides; fails closed when the store is down |
| R-015 admin counters in process | The portal accepts a shared Redis (`TS_REDIS_URL`); counters are then shared and fail closed | `m9-risk-fixes`: two portal instances on one Redis share one budget |
| R-026 base image by tag | `FROM` lines pinned by tag and digest | `ci-hygiene.test.ts` |
| R-029 location triangulation (partly) | A per-person location cap across all participants (default 8 per hour) | `m9-risk-fixes`: organisation B cannot restart organisation A's count |
| R-033 unpriced signal blocks billing | Migration 007: database triggers refuse an unpriced entitlement and a plan that leaves an entitled signal unpriced | `m9-risk-fixes`; existing price-plan test fixtures now price every entitled signal |
