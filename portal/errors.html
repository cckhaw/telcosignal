Errors and results

What each error code and signal result means, and what to do about it.

On this page
  • HTTP errors
  • Signal results

HTTP errors#

CodeHTTPMeaningWhat to do
INVALID_REQUEST400The request did not match the published schema (unknown field, wrong type, bad format, missing purpose or consent reference).Compare the request with the OpenAPI definition; unknown fields are rejected.
AUTHENTICATION_FAILED401Token, client certificate binding, signature or client assertion could not be verified.Fetch a new token with the SAME client certificate; check the key id, clock and signature payload.
ACCESS_DENIED403The caller is authenticated but not permitted: scope not granted, signal or purpose not entitled, or the participant is suspended.Request the scope or entitlement through your onboarding contact.
CONSENT_REQUIRED403No valid consent or lawful-basis reference for this subject, purpose and signal (missing, expired, revoked or not permitted). The reason is deliberately not disclosed.Register or renew the consent before asking for the signal.
REPLAY_REJECTED401The signed request is outside the time window or its identifier was already used.Use a fresh unique request id and a current timestamp; do not retry an identical signed request.
RATE_LIMITED429A rate limit or quota was exceeded.Back off and retry later; ask for a higher quota if the volume is legitimate.
PAYLOAD_TOO_LARGE413The request body exceeded the size limit.Send only the documented fields.
NOT_FOUND404No such resource for your organisation (the same answer is given for other organisations' resources).Check the identifier.
INTERNAL500An unexpected platform error. Details are never returned to the caller.Retry later and quote the correlation id.
SERVICE_UNAVAILABLE503A security dependency (for example the replay or rate-limit store) is unavailable, so the platform refuses to serve (fail closed).Retry with backoff and quote the correlation id.

Signal results#

ResultMeaningWhat to do
TRUEThe signal is positive (for example a SIM swap occurred in the window).Apply your own risk policy.
FALSEThe telco explicitly answered that the signal is negative. It is NEVER returned for a timeout, error or unsupported signal.Apply your own risk policy.
UNAVAILABLENo reliable answer: timeout, telco fault, invalid telco response, unrouted number, circuit open, or the signal is disabled. Indistinguishable from an unknown number by design.Treat as unknown (not as safe); retry later or use another control. Not charged.
NOT_SUPPORTEDThe serving telco does not provide this signal.Use another control for this subscriber. Not charged.

Error responses never reveal internals and never disclose whether a number exists.
