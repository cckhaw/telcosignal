How a request works#

  1. Connect with mutual TLS using your registered client certificate (TLS 1.3 preferred, 1.2 minimum).
  2. Obtain a short-lived access token with private_key_jwt; it is bound to your certificate.
  3. Register a consent or lawful-basis reference for the subject, purpose and signal.
  4. Call a signal endpoint with a signed request, the purpose code and the consent reference.

Signal safety#

Unknown is not safe

Answers are four-state. FALSE is only ever returned when the telco gave an explicit, valid negative. A timeout, an error, an invalid response, an unrouted number or an unsupported signal is returned as UNAVAILABLE or NOT_SUPPORTED, never as "no swap", "no forwarding" or "match". Treat these as unknown, not as safe. They are not charged.

Privacy#

Numbers are never stored

Phone numbers are never logged or stored by the platform (only keyed hashes). Identity attributes sent for KYC match are processed in memory only. Every request needs a purpose code and a consent reference.
